# ntut-course-planning-system
NTUT Computer Programming Group Project

F4 校園活動與教室配置：執行 `python main.py`，主選單選擇 `4`。
支援新增、取消、修改、查詢、學生報名及場地試算；活動與報名保留於本次執行期間，返回主選單再進入仍會保留。
教室取自 `data/classrooms.json`，可新增 `equipment` 字串清單；未設定代表無設備。
F4 使用提供的北科大鐘點表（`modules/period_times.py`），不需逐節輸入；課程與活動共用 `modules/conflict.py` 檢查。第 1～4 節為 08:10～12:00，第 5～9 節為 13:10～18:00，各節 50 分鐘；a 為 18:30～19:20、b 為 19:20～20:10、c 為 20:20～21:10。
目前課程格式支援 1～9、a～c，不含 N 或 D 節；午間仍可安排活動，並依實際起訖時間檢查活動之間的衝突。

活動輸入包含代號、名稱、日期、開始／結束時間、預計人數（同時作為報名上限）、類型及設備需求。
日期使用 `YYYY-MM-DD`，時間輸入使用四位數 `HHMM`，例如 `0800`、`1830`，不需冒號（臺灣時間，同日）；修改時空白保留原值，設備輸入 `-` 清空。
系統優先配置容量最小且符合全部條件的教室；修改會優先保留原教室，並重新檢查場地及原報名學生的時間衝突。
取消會移除活動、清除報名並釋放場地。報名不能超過活動或教室容量，也不能與學生既有課程或活動重疊。

輸出範例（虛構教室 R1 容量 2）：

```text
活動新增成功。
A1 程式講座（講座） 2026-11-18 12:00～13:00 教室：R1 報名：0/2 教室容量：2
設備需求：投影機
```

若預計人數為 3 且需要麥克風，而 R1 僅有投影機：

```text
可用教室：無合適教室
R1：容量 2 小於預計人數 3；缺少設備 麥克風
```

F4 驗收：`python -m unittest discover -s tests -p 'test_activity*.py'`。
核心測試建立十項不同活動，並涵蓋三十人報名、第三十一人遭拒、取消後重用場地、活動與課程衝突、設備不足及修改失敗保留原資料；介面測試涵蓋新增至取消的完整流程。
